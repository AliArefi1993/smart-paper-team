## Problem and scope

The [Product brief](2026-10-06-audit-followups-product.md) defines acceptance criteria. Source confirms Ideas replaces writing without a guard and stores body-only new drafts, Finance deletes immediately, and Settings saves from its top. Preserve existing local-data boundaries, deliberate commits, navigation and app palette. No timer change: its current controls have no established gap requiring this cycle.

## Interaction handoff

Ideas keeps the current writing-first layout and optional sparks. Save/Keep thought remains primary. One recoverable draft retains exact body, new/edit/branch mode, target/origin and the edit baseline. Legacy raw text restores as new; malformed structured drafts show a recovery error, never overwrite existing storage with blank initialization. Draft means unfinished writing, not a saved note.

Before Edit, Branch, or Cancel displaces dirty writing, use the existing native confirmation: “Discard unsaved writing? Continuing discards current writing. Keep editing to save it first.” / «نوشته ذخیره‌نشده کنار گذاشته شود؟ ادامه دادن نوشته فعلی را کنار می‌گذارد. برای ذخیره، ابتدا ویرایش را ادامه دهید.» Cancel preserves exact text/context. Confirm executes only that requested transition. Unchanged edit body is not dirty. Deleting a draft's target/origin must retain its writing and surface missing-context recovery, or explicitly guard discard.

Missing origin/target: retain text and context visibly; explain “The original thought is missing. Your writing is retained.” / «فکر اصلی موجود نیست. نوشته حفظ شده است.» Offer explicit “Keep as new thought” / «نگه‌داشتن به‌عنوان فکر تازه» and Cancel/discard guard. Never silently convert mode or save. Stale edit: show “The saved thought changed. Review both versions before choosing how to keep your writing.” / «فکر ذخیره‌شده تغییر کرده است. پیش از انتخاب روش نگه‌داشتن نوشته، هر دو نسخه را بررسی کنید.» Keep recovered writing editable and latest saved text readable in an expandable labelled region; explicit Keep as new thought preserves both. No overwrite action is required. Reread authoritative notes before mutation; preserve unrelated newer notes.

Draft failures use localized alert adjacent to composer and reachable retry. Writing failure: “Draft recovery could not be saved. Your writing is here, but may be lost after closing. Retry before leaving.” / «پیش‌نویس برای بازیابی ذخیره نشد. نوشته اینجاست، اما ممکن است پس از بستن از دست برود. پیش از خروج دوباره تلاش کنید.» Read failure leaves stored draft untouched and offers Retry loading. Note save failure retains body/mode with Retry saving. Note success plus cleanup failure says “Thought saved. Old draft cleanup failed; retry cleanup before leaving. Do not save again.” / «فکر ذخیره شد. پاک‌کردن پیش‌نویس قبلی انجام نشد؛ پیش از خروج دوباره تلاش کنید. دوباره ذخیره نکنید.» Retry cleanup must not create another note; persisted commit identity prevents stale recovery duplicating it. Storage errors never print raw private contents. Normal successful draft writes need no noisy per-keystroke announcement.

Finance uses the existing native confirm before mutation: “Delete this income entry? This entry will be removed. This cannot be undone.” / «این درآمد حذف شود؟ این درآمد حذف می‌شود. این کار قابل بازگشت نیست.» Cancel changes no record, totals or edit state. Confirm deletes once; pending disables repeated mutation; failure keeps the record and existing localized error. Only present details inside the unlocked screen.

Settings keeps one validated batch operation and its top action; repeat the same Save settings action after all ten sections and notification controls. Both placements share handler, disabled/pending state, validation and status. Invalid input remains editable with specific validation and focus at first invalid field; retry does not require re-entry. Apply happens only by explicit submit, never typing or toggling permission on entry. End action is in normal flow, not a fixed overlay competing with keyboard.

## Components, languages and accessibility

Affected emphasis/target controls only: existing Ideas Keep thought/Save changes and new recovery retry/Keep as new thought; Finance Save goal, Add income and inline edit Save; Settings top and end Save settings. Preserve semantic labels. Use existing shared primary Light/Dark role styling and minimum 44px touch targets (48px preferred primary), wrapping label, logical gap/margins and visible focus. Destructive commands remain distinct from primary. No blanket class or Timer sweep.

Phone composer, status and actions stack and wrap within 360–390px; wide layout follows existing max-width. Persian uses Vazirmatn and RTL; textarea content direction follows user text where available; numbers remain legible. Reuse teal/surface/ink/error roles from [foundations](foundations.md). Errors use alert, positive recovery/save feedback uses polite status, with words alongside color. Label every input. Native confirmation supplies platform focus/Back/Escape semantics; return focus to composer after Ideas transition, and to Finance trigger after cancellation. No sticky keyboard-obscuring controls. Busy actions expose saving state. Native keyboard, Back/process recreation and TalkBack are release follow-ups, not browser passes.
