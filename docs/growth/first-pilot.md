# First early-user pilot — proposal

Prepared: 2026-10-16. Status: draft for maintainer review; no invitations sent, pilot started, or results collected. Preparation is authorized; outreach is not. Persian copy is a draft pending maintainer language review. Design: not applicable to app UI; these are text-only invitation and support materials.

## Aim and boundaries

Learn whether a small group can install Smart Paper, save one useful plan, and choose to return within seven days. Recruit **5–8 adult friends or colleagues who use Android**, through the maintainer's existing personal relationships (the user-selected route). Fit remains an audience hypothesis — **Needs confirmation**: people who already want a simple offline weekly planner and can comfortably use English or Persian. Language mix and availability are unconfirmed. Do not infer a broader audience from this convenience sample.

Zero spend, incentives, paid promotion, or new services. The maintainer sends personal invitations only after approving this package and authorizing outreach; no platform recommendation, public post, contact scraping, scheduled messages, or agent-sent outreach. Review the existing pre-user release authorization when the first real participant begins; the lead retains release decisions.

Each participant's window starts at their first confirmed install (day 0) and ends seven days later. One useful action: write one short, non-sensitive plan in a day note in the current Planner week, wait for successful automatic saving, and reopen that day to see it retained. Returning on a later day is optional, and is observed separately. Do not require Finance, imports, notifications, AI sharing, screenshots, diagnostic exports, or app changes. No telemetry, tracking links, or automatic collection is added.

## Quick start — English (send with the invitation)

For version **2026.10.29**, checked **16 October 2026**. Please use the official link below. If sharing later, the maintainer should confirm the chosen version and link first.

1. On your Android phone, open the [official release page](https://github.com/AliArefi1993/smart-paper-team/releases/tag/smart-paper-v2026.10.29). Under Assets, choose **SmartPaper-local-2026.10.29-release.apk** ([exact download](https://github.com/AliArefi1993/smart-paper-team/releases/download/smart-paper-v2026.10.29/SmartPaper-local-2026.10.29-release.apk)), not the source-code archives. Downloading needs internet; planning after installation works offline.
2. Open that APK. If Android requests permission for this browser/file app to install it, allow that source only if you are comfortable, then revoke that source permission afterward. Keep Play Protect and other security protections enabled. If installation is blocked or a warning is unclear, stop and reply to me; don't work around it. Installation and upgrades have not yet been verified on physical phones.
3. Open Smart Paper. Choose English or Persian in Settings if needed. In Planner, use the current week, open a day, and write one short, non-sensitive plan in its day note. Wait for the save status to confirm success. If saving fails, keep the app open and reply to me; don't assume it saved. Navigate away and reopen that day to check the note remains. You don't need to share its text.
4. If you wish, return on a later day when the plan is useful. A simple reply such as “installed”, “saved and reopened”, or “returned on another day” is enough; each is optional. Support and opt-out are by reply to me. No screenshots or private content are needed.

Records stay on this phone; there is no account or server sync. Android cloud app-data backup is excluded; supported phone-to-phone transfer is permitted but unverified. Before uninstalling or changing phones, keep a verified JSON backup outside the app. The Finance PIN is a screen lock, not encryption; Finance data and JSON backups are not encrypted, full JSON backup/import requires the PIN, and the app has no forgotten-PIN recovery. You can leave Finance unused. Local error recording and feature counts default on with visible controls; you can inspect, delete or turn them off. Reports are never automatically uploaded or sent. Native file handling, upgrade retention, transfer, notifications and TalkBack still lack physical-device evidence. Use non-sensitive trial entries. If data seems missing, stop changes/imports/uninstalling and reply to me promptly; do not send your backup or PIN.

## Launch decision and provisional decision rule

Recommendation: the maintainer may approve this bounded package and authorize personal invitations after reviewing the Persian draft and consent wording. No outreach is authorized by preparation alone. Physical-device gaps remain existing follow-ups, not newly invented release gates; disclose them as above.

These are small operational thresholds for a discussion, not statistical evidence. After all seven-day windows close: if fewer than five aggregate-consenting confirmed installs have known first-action and return outcomes, mark learning **inconclusive** and improve invitation/install clarity before considering another approved pilot. Do not chase missing answers or automatically recruit replacements.

Use the same eligible subset throughout: aggregate-consenting confirmed installs whose full seven-day window elapsed and whose first-action and return outcomes are known. If that subset contains at least five people, consider another similarly small pilot only when at least four within it report saving/reopening a plan and at least three within it report voluntary return on another day, with no unresolved serious data-safety/security issue. People who decline aggregate use, withdraw, or have unknown outcomes do not count as failures or toward those thresholds. Otherwise, separate installation friction from first-use friction and weak value/fit, then give Product one prioritized recommendation; do not automatically add features. Any suspected serious issue overrides the numeric rule and receives prompt triage. Lead and maintainer review the outcome and authorize any next outreach separately.
