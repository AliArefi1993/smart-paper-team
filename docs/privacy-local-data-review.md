# Android privacy and local-data protection review

Reviewed: 2026-10-09. Source: frontend `38f19c1a6a151fce04a02c951a06dab6ae9a1f76`, shipped Android 2026.10.10/code 27. [Task](../tasks/2026-10-08-privacy-local-data-review.md).

## Scope and conclusion

Bounded independent Security source/configuration review, accepted by lead. No high/critical finding was established within the current private, single-user Android/local-data boundary. This is not a runtime security certification. No personal data, secrets, device backups or diagnostic attachments were collected. No device tests, traffic captures, backup/restore or spreadsheet execution were performed. Frontend/backend behavior is unchanged.

Threats considered: casual access to an unlocked phone, sensitive notification previews, retained exports, OS migration/backup, malicious imported text and oversized imports. App-origin JavaScript, rooted/device-level access or extracted app storage can bypass the finance screen lock. Android/device protections are separate from application encryption.

## Ranked findings and bounded follow-up scopes

These were assessment priorities at the reviewed source revision. The finance-expiry finding was fixed in Android 2026.10.11. Explicit OS backup policy is implemented at frontend `d899f2c` and independently verified in the code 31 APK; [task and release status](../tasks/2026-10-10-android-backup-policy.md) distinguish validated configuration from untested OS/OEM behavior. Notification disclosure remains a follow-up. Severity assumes deliberate local use; no broad hosted or multi-user assessment was performed.

1. **Medium: finance remains rendered after unlock expiry. High value, low–medium effort.** [FinanceView](../smart-paper-front/src/components/finance-view.tsx#L78) polls using the full one-hour TTL and lacks focus/visibility rechecks. Mounting near expiry can leave stale finance visible almost another hour; suspended timers add uncertainty. Store reads/mutations still enforce expiry. Next implementation: bounded polling or remaining-expiry scheduling, recheck on focus/resume, and clear sensitive rendered/edit state on expiry. Cover near-expiry mounting, suspended return and stale asynchronous responses. Reuse [ExportView checks](../smart-paper-front/src/components/export-view.tsx#L78). Designer must define bilingual locked/unsaved-edit states before implementation; an immediate-lock action is a separate decision.

2. **Medium: implicit Android backup policy. High value, medium effort.** [Manifest](../smart-paper-front/android/app/src/main/AndroidManifest.xml#L5) allows backup without explicit rules. Android defaults cover most eligible app files and exclude cache; cloud and device-transfer controls vary by OS/OEM. This implies eligibility, not proof that this app's WebView data was uploaded. See [Android Auto Backup documentation](https://developer.android.com/identity/data/autobackup). Next scope: Product/lead choose an explicit cloud/D2D recovery policy, preserve recovery usability, configure applicable old/new rule formats and test actual WebView storage and unlock-deadline restore. Record Android/OEM versions and use synthetic data. Designer should explain OS backup/migration separately from app uploads; never promise that `allowBackup=false` alone prevents every device transfer.

3. **Medium: reminder event titles enter notification previews. Medium–high value, medium effort.** [Notifications](../smart-paper-front/src/lib/notifications.ts#L119) can expose appointment titles on the lock screen or connected surfaces. Actual display is untested. Next scope: ready EN/FA Settings story explaining preview exposure and an optional generic-body reminder; preserve existing opt-in behavior. Test actual lock-screen previews and platform settings before making privacy guarantees.

4. **Low: shared plaintext cache has no bounded cleanup. Medium value, low–medium effort.** [File helper](../smart-paper-front/src/lib/file-share.ts#L21) leaves files after success/cancellation/error; timestamped backups can accumulate. [Provider roots](../smart-paper-front/android/app/src/main/res/xml/file_paths.xml#L3) expose broader grantable external/cache paths than these flows need, though the provider itself is not public. Next scope: dedicated share directory, narrow paths, bounded age/count cleanup, and delayed recipient-read tests. Do not delete immediately when the chooser returns or claim secure deletion/recall of recipient copies.

5. **Low, conditional: CSV formula interpretation. Medium value, low effort.** [CSV formatting](../smart-paper-front/src/lib/export-format.ts#L28) quotes text without neutralizing formula prefixes. Crafted imported notes may execute as formulas when opened in a spreadsheet. No execution demonstrated. [OWASP CSV Injection guidance](https://community.owasp.org/attacks/CSV_Injection) explains that quoting alone is insufficient and sanitization varies by consumer. Next scope: define supported spreadsheet consumers, protect text cells and test prefixes/separators/quotes, preserving numeric fields and faithful JSON backups. Assess XLSX separately; do not assume equivalent exposure or universal sanitization.

6. **Low: unbounded import reads before validation. Medium value, low effort.** [Import](../smart-paper-front/src/components/export-view.tsx#L167) calls `file.text()` without a size gate. User-selected oversized files can stall/exhaust memory. Structural validation and best-effort rollback exist, but are not crash atomic. Next scope: documented pre-read byte limit and justified record/text limits, with EN/FA recovery states; oversized rejection must leave primary data untouched.

## Copy, errors and encryption

Existing [EN/FA PIN and JSON warnings](../smart-paper-front/src/lib/i18n.ts#L95) accurately disclose no encryption. Avoid duplicating them. Design-ready clarification scope: OS backup/migration caveat alongside device-storage wording; clipboard exposure and retained recipient copies beside report transfer; notification preview warning; and truthful share/download feedback. [Generic export success](../smart-paper-front/src/components/export-view.tsx#L138) ignores the helper outcome, so must not certify delivery or a recoverable backup. Cover EN/FA, cancellation, denied sharing and manual recovery in studio stories before implementation.

No deliberate personal-data logging was found in reviewed code. Screens sometimes render raw `Error.message` ([export](../smart-paper-front/src/components/export-view.tsx#L149), [finance](../smart-paper-front/src/components/finance-view.tsx#L88)); native errors may disclose filenames/paths and validator messages may remain English. Future error-handling work should map to stable localized codes. No raw exceptions or attachments should upload automatically.

Application encryption is a separate threat-model/recovery decision. A public four-digit PIN is unsuitable as its key. Device-bound keys complicate migration; passphrase-encrypted portable backups need explicit lost-key behavior. Prioritize expiry, backup policy and exposure disclosure before cryptographic redesign. This review does not weaken the requirement for external JSON backups and tested restore.
